# 前端重构说明

本次先阅读了 `public/assets/` 全部页面与数据处理，以及 `src/routes/`、`src/services/`、`src/repositories/`、输入校验、数据库结构和现有集成测试。项目实际是支出管理应用；经用户确认，重构当前财务项目并重点优化移动端。

## 保留的业务规则

- 邀请码注册、JWT 登录和按用户隔离的数据。
- 四种支出分类：购物/连载、食品、交通、订阅。没有收入表，因此不展示收入或虚构结余。
- `/api/data?month=…` 会同步该月月付订阅账单，再读取完整导出数据，避免首次刷新时两个视图不一致。
- 开启的订阅按月付原价、季度价÷3、年价÷12折算。预期支出仅为订阅月均与所选月份未付款连载之和；不会再叠加实际支出。
- 月付订阅自动入账，关闭后按现有服务端规则移除该月自动账单；季度/年付不伪造自动账单。年付在续订月份提醒。
- 连载结算使用原子的 `/serials/:id/advance` 接口，同时记账和更新下一期名称、价格、月份。默认下一期从该计划的发售月份推进一个月。
- 日/月/年统计、同名称同分类聚合排行、分类分布、年度月汇总、JSON 备份与 CSV 导出。
- 日均按有支出的日期平均，年度月均按 12 个月平均。预算为 0 时不计算使用率，不显示误导性的超支状态。
- AI 设置与缓存继续使用现有服务；日/月/年独立缓存，切换范围时丢弃过期响应。

## 信息架构和实现

- `components.js`：图标、通用表单、对话框、登录、记账、订阅/连载编辑、结算、预算、删除确认、导入和 AI 设置。
- `views.js`：桌面侧栏/手机底栏，以及总览、账单、订阅、连载、统计和设置页面。
- `main.js`：认证、数据请求、过期响应保护、操作协调、导出和路由状态。
- `utils.js`：金额和日期处理、聚合、预估与 CSV 解析。CSV 支持 BOM、CRLF、引号、名称内逗号和转义引号，错误行会明确提示，不静默漏导。
- `styles.css`：设计变量和原生 CSS，删除浏览器中 Tailwind 的运行时编译。
- `scripts/build-frontend.js`：使用已有本地 Babel 将 JSX 编译为 `public/assets/compiled/`。浏览器不再下载 Babel 或 Tailwind，未增加 npm 依赖。

运行 `npm run build` 更新编译产物；`npm start` 会自动构建。保留 `node app.js` 的原有启动方式，发布时应包括已编译目录和 React vendor 文件。JSX 源文件和编译产物一起保留在仓库。

## 移动端体验

- 底部「总览 / 账单 / 记一笔 / 计划 / 统计」，主操作靠近拇指。
- 月份置于顶部，总览首屏可以看到最近账单的开头。
- 表单是可滚动的底部面板，使用动态视口高度和安全区域留白。
- 金额使用数字键盘提示；保留页面缩放能力。名称/日期有清晰标签。
- 「保存并继续记」保留分类和日期，清空金额/名称并重新聚焦；请求失败不关闭表单或清空输入。
- 保存有提交锁和状态提示，避免重复点击。对话框支持 Escape、焦点约束、关闭后焦点恢复和背景滚动锁定。
- 账单整行点击编辑，支持关键词、分类筛选与分批加载。长名称限制视觉行数，完整名称仍可在编辑表单查看。
